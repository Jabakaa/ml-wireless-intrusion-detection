# Machine Learning-Based Wireless Intrusion Detection System (WIDS)

## Project overview
This project is a reproducible **educational prototype** that demonstrates how a machine-learning classifier can identify traffic patterns resembling Wi-Fi deauthentication floods. It uses a **synthetic dataset** so it can run in Google Colab without a monitor-mode adapter or transmitting attack traffic.

**Important:** The data are simulated. Reported accuracy measures performance on a held-out synthetic test split only; it is not evidence of performance on a real wireless network. This repository does not capture packets, transmit deauthentication frames, disconnect clients, or block MAC addresses.

## Features
- Generates synthetic normal and deauthentication-flood-like traffic windows.
- Uses five features: frame type code, simulated signal strength (RSSI), frames per second, deauthentication frames per second, and unique destination count.
- Trains a scikit-learn Random Forest classifier.
- Reports accuracy, precision, recall, F1-score, and a confusion matrix.
- Produces a confusion-matrix image and feature-importance chart.
- Prints sample detection alerts.

## Quick start: Google Colab
1. Upload `WIDS_Colab_Demo.ipynb` to Google Colab, or open the notebook in Colab from GitHub.
2. Run all cells from top to bottom.
3. The notebook installs/uses common Python libraries, generates the synthetic data, trains the model, displays evaluation metrics, plots the confusion matrix, and prints example alerts.
4. Download the output files from the `results/` directory if needed.

## Run locally
Python 3.10+ is recommended.

```bash
python -m pip install -r requirements.txt
python wids_prototype.py
```

The script writes metrics and figures to `results/`. If running locally, ensure the `results` directory exists before running the script, or create it first with `mkdir results`.

## Architecture
Synthetic traffic generator → feature extraction → train/test split → Random Forest classifier → metrics and confusion matrix → alert output.

## Dataset and labels
Each row represents a simulated observation window for a wireless device. Label `0` means normal and label `1` means malicious-like traffic. Attack-like rows are generated with higher frame rates, more deauthentication frames per second, and more unique destinations. This creates a simple demonstration dataset, but it may make classification easier than real-world detection.

## Features used
| Feature | Meaning |
|---|---|
| `frame_type_code` | Encoded frame category: management=0, control=1, data=2 |
| `signal_strength_dbm` | Simulated received signal strength indicator (RSSI) |
| `frames_per_second` | Estimated frames observed per second in a device/window |
| `deauth_frames_per_second` | Deauthentication frames observed per second in a window |
| `unique_destination_count` | Number of distinct destinations contacted in a window |

## Safety and limitations
- Synthetic traffic only; no live packet capture or attack generation.
- No real access point or client is targeted.
- No prevention or blocking functionality is implemented; this is WIDS, not WIPS.
- Synthetic distributions are simplified and may not represent actual Wi-Fi behaviour.
- Real deployment would require authorised monitor-mode captures, robust labels, time-based evaluation, false-positive testing, and validation across different devices and environments.
